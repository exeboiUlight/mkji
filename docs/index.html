MKJI

MKJI — компилируемый язык программирования с C-подобным синтаксисом и собственным self-hosted компилятором. Компилятор написан на MKJI и генерирует нативные исполняемые файлы напрямую: PE64 для Windows и ELF64 для Linux x86-64, без внешнего ассемблера и линковщика.

На этой странице собрана подробная документация по языку, компилятору, проектам, инструментам и примерам использования.

.mk исходники PE64 / ELF64 Self-hosted compiler CLI, проекты, use, классы, массивы

Что такое MKJI

MKJI — это язык со знакомым синтаксисом в стиле C: функции, блоки { }, инструкции с ;, условия, циклы, классы, массивы и явные типы. Компилятор транслирует исходный код в машинный исполняемый файл целевой платформы.

Основные возможности

  • Типы: int, bool, string, byte, void, классы и массивы
  • Функции, параметры, возвращаемые значения
  • Классы с полями, методами, this, init и new
  • Условия if/else, циклы while, return
  • Массивы, строки, индексация, свойство .len
  • Встроенные функции для вывода, файлового ввода-вывода, аргументов и др.
  • Подключение исходников через use "file.mk";
  • Импорт функций из динамических библиотек через extern (DLL на Windows, .so на Linux)
  • Сборка одиночных файлов и проектов по манифесту

Компилятор

  • Готовые бинарники: mkji.exe (Windows) и mkji_elf (Linux x86-64)
  • Цели: pe и elf
  • Режимы: прямая компиляция, проектная сборка, создание проекта, legacy-режим через mkji_build.txt
  • Исходники компилятора: каталог src/, точка входа src/main.mk

Быстрый старт

1. Компиляция одного файла

Windows (PE64):

.\mkji.exe examples\hello.mk -o hello.exe --target pe
.\hello.exe

Linux / WSL (ELF64):

./mkji_elf examples/hello.mk -o hello --target elf
chmod +x hello
./hello

2. Минимальная программа

print("hello from MKJI!");
int x = 10;
int y = 32;
print(x + y);

3. Создание и сборка проекта

.\mkji.exe new Demo
.\mkji.exe build DemoProjects.mk

Команда new создаёт файл манифеста <Name>Projects.mk и исходник <Name>.mk.

4. Legacy-режим

Если запустить компилятор без аргументов, он читает mkji_build.txt из текущего каталога (3 строки: входной файл, выходной файл, цель).

src/main.mk
mkji.exe
pe

CLI компилятора

Команда / формаОписание
mkji Legacy-сборка: читает mkji_build.txt (вход, выход, цель).
mkji <file.mk> [-o <out>] [--target pe|elf] Прямая компиляция одного входного файла. Поддерживаются также формы --target=pe, --target=elf.
mkji build <Project.mk> Сборка проекта по манифесту. Требуется явный путь к файлу проекта.
mkji new <Name> Создаёт шаблон проекта: <Name>Projects.mk и <Name>.mk.
mkji help / --help / -h Показывает справку по использованию.

Поведение по умолчанию

  • Цель по умолчанию: pe.
  • Если -o не указан, имя выхода выбирается по имени входного файла: .exe для PE, .elf для ELF.
  • Алиас цели: linux трактуется как elf.
  • При успешной компиляции печатается путь входа и выхода, затем сообщение о завершении.

Проекты и манифесты

Проект описывается текстовым манифестом (обычно *Projects.mk) с парами ключ/значение по строкам.

Поддерживаемые ключи

КлючОбязательностьНазначение
main:обязательныйПуть к главному исходному файлу (.mk).
target:необязательныйЦелевая платформа: pe или elf (linux = elf). По умолчанию pe.
output:необязательныйПуть к выходному файлу. Если не задан, выводится из main.
lib:необязательный, повторяемыйДополнительные исходники/библиотеки, которые парсятся в ту же программу перед main.

Пример манифеста

main: src/main.mk
target: elf
output: build/app
lib: src/core/utils.mk
lib: src/core/math.mk
Сборка проекта объединяет указанные lib-файлы и main в одну компилируемую программу. Дополнительно внутри исходников можно использовать use для включения файлов.

Массивы

Массивы задаются суффиксом [] после базового типа:

  • int[]
  • byte[]
  • string[]
  • MyClass[] (массив ссылок на объекты класса)
int[] nums = new int[3];
byte[] buf = new byte[16];
string[] names = new string[2];
Point[] points = new Point[10];
Точное статическое поведение и проверки типов зависят от текущей реализации компилятора. В пользовательском коде рекомендуется явно придерживаться согласованных типов объявлений, параметров и возвращаемых значений.

Переменные и объявления

Объявление с явным типом

int x = 10;
bool ok = true;
string name = "MKJI";
Point p = new Point(1, 2);

Форма объявления: <тип> <имя> [= <выражение>];

  • Объявления могут встречаться на верхнем уровне и внутри блоков/функций.
  • Внутри функций локальные переменные сохраняются в локальной области функции; на верхнем уровне — как глобальные/верхнеуровневые переменные программы.
  • var не поддерживается.

Присваивание

Присваивание — выражение вида цель = значение. В качестве цели поддерживаются:

  • переменная: x = 5;
  • поле объекта: p.x = 10;
  • элемент массива/строки по индексу: arr[i] = 1;
int x = 1;
x = x + 1;

Point p = new Point(0, 0);
p.x = 7;

int[] a = new int[2];
a[0] = 100;

Инструкции

Блок

{
    int x = 1;
    print(x);
}

Условие if / else

if (x > 0) {
    print("positive");
} else {
    print("non-positive");
}

Ветви могут быть блоком или одиночной инструкцией.

Цикл while

int i = 0;
while (i < 3) {
    print(i);
    i = i + 1;
}

Возврат return

fn int inc(int x) {
    return x + 1;
}

fn void log_done() {
    print("done");
    return;
}

Пустая инструкция

;
В текущем синтаксисе нет for, break и continue.

Функции

Объявление функции начинается с fn, затем указывается тип возвращаемого значения, имя, список параметров и тело-блок.

fn int add(int a, int b) {
    return a + b;
}

fn void greet(string name) {
    print("hello");
    print(name);
}
  • Параметры объявляются с явными типами.
  • Функции могут вызывать другие функции и сами себя (рекурсия поддерживается).
  • Функции могут объявляться на верхнем уровне и как методы внутри классов.

Классы и объекты

Объявление класса

Класс может содержать поля и методы. Поля объявляются как <тип> <имя>;, методы — как функции с fn.

class Point {
    int x;
    int y;

    fn void init(int px, int py) {
        this.x = px;
        this.y = py;
    }

    fn int sum() {
        return this.x + this.y;
    }
}

Создание объектов и init

  • Объект создаётся через new ClassName(...).
  • Если в классе определён метод init, он вызывается автоматически при создании объекта с переданными аргументами.
  • this доступен внутри методов и ссылается на текущий объект.
Point p = new Point(3, 4);
print(p.x);      // 3
print(p.sum());  // 7

Доступ к полям и методам

p.x = 10;            // запись поля
int y = p.y;         // чтение поля
int s = p.sum();     // вызов метода

Массивы объектов

Point[] points = new Point[2];
points[0] = new Point(1, 2);
points[1] = new Point(3, 4);
print(points[0].sum());

Массивы и строки

Создание массивов

Массивы создаются через new с указанием типа элемента и длины:

int[] nums = new int[3];
byte[] buf = new byte[4];
string[] words = new string[2];

Индексация и длина

  • Доступ по индексу: a[i]
  • Длина массива/строки: a.len, s.len
int[] nums = new int[3];
nums[0] = 10;
nums[1] = 20;
nums[2] = 30;
print(nums[1]);   // 20
print(nums.len);  // 3

string s = "ABC";
print(s[0]);      // код/значение элемента
print(s.len);     // 3

Строки и байтовые буферы

string s = "ABC";
byte[] buf = new byte[3];
buf[0] = s[0];
buf[1] = s[1];
buf[2] = s[2];

bool ok = write_file("out.txt", buf);
string text = read_file("out.txt");

Встроенные функции

ФункцияНазначениеПримечания
print(x) Вывод значения (с переводом строки). Поддерживает типы, для которых в рантайме есть вывод (числа/bool/строки/объекты и т.д.).

print(arg_count());

string a1 = get_arg(1);
print(a0);
print(a1);

Подключение файлов (use)

Инструкция use включает другой исходный файл на этапе разбора:

use "lib.mk";
use "utils/math.mk";
  • Синтаксис: use "<path>";
  • Относительные пути разрешаются относительно файла, в котором написан use.
  • Повторное включение одного и того же файла пропускается (защита от повторного подключения).
  • Если файл не найден или не может быть прочитан, компиляция завершается ошибкой.

Внешние функции (FFI, extern)

MKJI позволяет объявлять и вызывать функции из внешних динамических библиотек: DLL на Windows (PE64) и разделяемых библиотек .so на Linux (ELF64).

Синтаксис

Блочная форма (несколько функций из одной библиотеки):

extern "kernel32.dll" {
    fn int GetCurrentProcessId();
    fn void SetLastError(int err);
    fn int GetLastError();
}

Одиночная форма:

extern "libc.so.6" fn int getpid();

Явное имя экспортируемого символа с помощью as (если имя символа в библиотеке отличается от имени в MKJI):

extern "kernel32.dll" fn int GetTickCount() as "GetTickCount";

Семантика и соглашения

  • В блоке extern "lib" { ... } объявляются сигнатуры функций (тип возврата, имя, параметры). Имена параметров можно опускать.
  • Объявленные внешние функции вызываются так же, как обычные функции MKJI.
  • string при передаче во внешнюю функцию маршалится как указатель на данные строки (C-совместимая последовательность байтов); значение null передаётся как нулевой указатель.
  • byte[] передаётся как указатель на данные массива; null — как нулевой указатель.
  • Значения других типов передаются напрямую; возвращаемое значение берётся из регистра результата (RAX).

Поддержка платформ

ЦельБиблиотекиСтатус
Windows, --target pe DLL (например, kernel32.dll, user32.dll) Поддерживается: импорт через таблицу импорта PE, вызов через IAT
Linux x86-64, --target elf Разделяемые библиотеки .so (например, libc.so.6) Поддерживается: динамическое связывание (GOT/динамические релокации), требуется интерпретатор /lib64/ld-linux-x86-64.so.2
Имя библиотеки указывается строкой так, как его ожидает загрузчик целевой платформы (например, kernel32.dll в Windows или libc.so.6 в Linux).

Структура программы

  • Исходный файл имеет расширение .mk.
  • Программа состоит из последовательности инструкций и объявлений (функции, классы, переменные, выражения, use и т.д.).
  • Инструкции верхнего уровня поддерживаются и выполняются как точка входа программы.
  • Функции и классы могут объявляться в исходном тексте; объявления классов содержат поля и методы.
use "lib.mk";

fn int twice(int x) { return x * 2; }

class Box {
    int v;
    fn void init(int n) { this.v = n; }
}

Box b = new Box(21);
print(twice(b.v));

Ошибки и диагностика

Текущая реализация компилятора при фатальных ошибках обычно завершает работу с текстовым сообщением (без единого формата с кодами ошибок и координатами файл:строка:столбец во всех случаях).

Примеры сообщений компилятора

  • expected punctuation, expected keyword, expected end of file
  • expected expression, invalid assignment target
  • expected type name, expected variable name, expected function name, expected class name
  • typed declarations only (для var)
  • use expects a string path, cannot open included file
  • duplicate class, only fields and fn allowed in class
  • new expects class or array type
  • Сообщения CLI вида mkji: ... (например, отсутствие входного файла проекта/манифеста, ошибки чтения/создания файлов)

Ошибки времени выполнения (рантайм)

Скомпилированные программы могут завершаться аварийно при некоторых условиях выполнения, например:

  • разыменование null / недопустимый доступ к объекту
  • вызов отсутствующего метода (в зависимости от ситуации диспетчеризации)
  • нехватка памяти при выделении
  • явный вызов panic(...)
Для удобной работы в редакторе используйте анализатор tools/mkji-analyzer.py и/или расширение VSCode: они могут предоставлять диагностику с координатами и дополнительными проверками поверх поведения компилятора.

Инструменты

Статический анализатор

Файл: tools/mkji-analyzer.py

  • Проверяет .mk файлы и каталоги рекурсивно
  • Сообщает о лексических/структурных проблемах с позициями строка:столбец
  • Может дополнительно запускать компилятор для выявления ошибок компиляции
  • Форматы вывода: text, vscode, json
python tools/mkji-analyzer.py --format text src/main.mk
python tools/mkji-analyzer.py --format vscode --compiler ./mkji.exe examples/hello.mk

Расширение VSCode

Каталог: vscode-mkji/

  • Подсветка синтаксиса для .mk
  • Конфигурация языка (комментарии, скобки, авто-закрытие)
  • Диагностика ошибок при открытии/сохранении и по командам
  • Интеграция с анализатором и/или компилятором

См. vscode-mkji/README.md для настройки путей к Python, анализатору и компилятору.

Функции, классы, циклы

class Point {
    int x;
    int y;

    fn void init(int px, int py) {
        this.x = px;
        this.y = py;
    }

    fn int sum() {
        return this.x + this.y;
    }

    fn string describe() {
        return "Point";
    }
}

fn int twice(int n) {
    return n * 2;
}

Point p = new Point(3, 4);
print(p.describe());
print(p.x);
print(p.sum());
print(twice(p.sum()));

int i = 0;
while (i < 3) {
    print(i);
    i = i + 1;
}

Ограничения и текущий статус

  • Компилятор и язык активно развиваются; поведение и набор диагностик могут расширяться.
  • Формат ошибок компилятора сейчас в основном текстовый (без стабильных кодов/координат во всех сообщениях).
  • В языке отсутствуют некоторые конструкции, привычные по другим языкам (например, for, break, continue).
  • Часть семантических проверок и удобства диагностики может быть реализована на уровне внешних инструментов (анализатор, расширение редактора).
  • Проектная модель проста: манифест на строковых ключах и сборка указанных исходников в одну программу.

Пересборка компилятора

Компилятор сам написан на MKJI, поэтому его можно пересобирать уже собранным компилятором.

Windows

.\mkji.exe src\main.mk -o mkji.exe --target pe

Также можно использовать legacy-режим из корня проекта, если mkji_build.txt настроен на сборку src/main.mk.

Linux / WSL

./mkji_elf src/main.mk -o mkji_elf --target elf
chmod +x mkji_elf

Тесты

powershell -ExecutionPolicy Bypass -File tests/run_pe_tests.ps1
sh tests/run_elf_tests.sh
